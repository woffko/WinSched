## Windows-native matrix

Ten substantive native test executables ran serially in interactive session 1;
zero-test GUI entry binaries were excluded. All 152 tests passed.

| Area | Result | Notable coverage |
|---|---:|---|
| Platform and diagnostics | PASS | Win32 process APIs, cancellable overlapped pipe, atomic replace, memory notification and WASAPI initialization |
| Core/config/control | PASS | topology, reserve rounding, profiles, migration to schema 4, bounded status/reload semantics |
| Service | PASS | 52 tests including WAL migration/recovery, per-property ownership, partial restore bookkeeping, external override plus visible veto, wake coalescing |
| Settings/tray | PASS | defaults, repeated atomic saves, single-instance model, About/menu state |
| Negative pipe authentication | PASS | authenticated current-process client rejected when expected image path differs; no state and no wake published |

The dedicated parent/child test produced an important safety result: a
`ping.exe` created after its `cmd.exe` parent was changed inherited the parent's
memory priority, but not its EcoQoS state in this scenario. Restoring the parent
did not retroactively restore the live child. Consequently the Background
master switch and both process-level mutations ship disabled; users must opt in
only for a tested leaf workload.

## Explicitly unexecuted environment gates

- A real Windows LowMemory/HighMemory notification transition was not forced;
  handle initialization, query behavior, retained-last-state logic, and policy
  transitions are covered without deliberately exhausting VM memory.
- Multi-interactive-session quorum was not run because the designated VM had
  one active interactive session. Session intersection and fail-closed quorum
  behavior are covered by native tests.
- A real render/capture audio stream veto was not run because this VM has no
  acceptance-grade audio endpoint. WASAPI initialization/enumeration and
  fail-closed audio-probe behavior are covered by native tests.
