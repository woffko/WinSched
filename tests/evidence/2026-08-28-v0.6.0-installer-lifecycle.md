## Regression detected and corrected

The first Setup candidate, SHA-256
`67dea2dab237110ea52908ffb3adac2d2871efd88fa2404800ca64d510b2bd7f`,
passed the 0.5.1 to 0.6.0 upgrade but failed a second Setup run before any
uninstall or purge stage. Its Inno log reported that `PrepareToInstall` could
not secure the Program Files directory and returned exit code 7. The lifecycle
harness restored the original configuration, Scheduling state, and Running
service.

The cause was an incomplete ACL-helper allowlist: the new
`winsched-monitor.exe` existed after the first upgrade but was not accepted on
the next hardening pass. The correction adds Monitor to the Application and
Data allowlists. `build-gui-installer.ps1` now parses the `secure-data.ps1`
inside the frozen payload and evaluates its allowlist against every packaged
file before compiling Setup.

The preserved diagnostic receipts are:

- `runtime/v0.6.0/installer-lifecycle-regression-detected.json`
- `runtime/v0.6.0/setup-error-receipt-regression-detected.json`

## Exact 0.5.1 to 0.6.0 upgrade

The accepted 0.5.1 Setup
`4c92f9ef2d4c10662bc86c042a0f9df09cc9553c3b94b738be6383325c760d3d`
was installed after a scoped purge on the test VM. The accepted final 0.6.0
Setup was then run over it. The test verified:

- exact old and current Setup hashes and versions;
- a marked schema-5 configuration remained byte-identical;
- Scheduling, configured mode, and logging level were preserved;
- `winsched-monitor.exe` and the Process Monitor shortcut were added;
- all five installed executable hashes matched the frozen payload;
- the service remained Running with status schema 5;
- the original 0.6.0 configuration, Scheduling state, service, and payload were
  restored after the comparison.

The authoritative privacy-minimized receipt is
`runtime/v0.6.0/gui-upgrade-result.json`.

## Boundary

This VM result proves the tested installation, rollback, preserve/purge,
shortcut, configuration, service, and repeat-install contracts. It does not
prove physical Threadripper performance. The separate physical Process Monitor
smoke remains pending, and the accepted Setup is not Authenticode-signed.
